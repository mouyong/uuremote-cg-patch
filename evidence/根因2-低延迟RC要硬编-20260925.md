# 根因二：VideoToolbox 低延迟码率控制强制要硬件编码器（无画面·第二道门）

- 机器：本机 108 = 2011 Mac mini（Macmini5,2）+ OCLP macOS 15.7.9 —— **无 Metal、无硬件 H264 编码器**
- 对象：UU远程 4.40.0，`libstreamer.dylib`
- 日期：2026-09-25
- 前置：根因一（Metal 门禁）已于 13:35 装机修复，`Failed to create metal device / error 12` 消失

## 一句话结论

`ResetVTCompressionSession()` 给 encoderSpec 无条件写
`encoderSpec[kVTVideoEncoderSpecification_EnableLowLatencyRateControl] = kCFBooleanTrue`，
而 VideoToolbox 的「低延迟码率控制」**强制要求硬件编码器**。本机只注册了
`com.apple.videotoolbox.videoencoder.h264`（Apple H.264 **SW**）→ `VTCompressionSessionCreate` 返回
`kVTParameterErr (-12902)` → 编码器建不起来 → 零帧 → 控制端永远「正在传输画面」。
系统日志同时给出：`(VideoProcessing) Low latency RC mode requires hardware encoder`。

★ 关键：**只把硬件加速键改成 false 没用**（根因一的一处旧补丁就改了它），因为低延迟这个键本身依然存在。

## 证据链

### 1) 现场（连接期间）
- 采集侧完全正常：`/tmp/uushim.log` 出帧 64 帧 / 8FPS / 420v NV12 / 1920x1080（13:44:32~40）
- 但网络发送量只有 **~380 B/s**（心跳量级，无视频流）
- `VTEncoderXPCService` 存在但 CPU ≈ 0（空转）
- 系统日志：`13:44:32.929 E UURemoteServer (VideoProcessing) Low latency RC mode requires hardware encoder`

### 2) VideoToolbox 参数矩阵（本机 vs 对照机）
| 组合 | 本机 108（无硬编） | Air M2（有硬编） |
|---|---|---|
| hw=T + 低延迟=T（**原版行为**） | ❌ create = -12902 | ✅ 成功、出码 7 帧 |
| hw=F + 低延迟=T（**只改 hw 的补丁**） | ❌ create = -12902 | ❌ 失败 |
| hw=F + 低延迟=F / 不设 | ✅ 成功、出码 8 帧 | ✅ 成功 |
| 不指定任何 spec | ✅ 成功 | ✅ 成功 |

⇒ 失败点唯一：**低延迟 RC 要求硬件编码器**。

### 3) 补齐 UU 属性集后再验（软件编码器）
关掉低延迟后，把 UU 实际会设的一整套属性都设上，仍稳定出码：
```
RealTime / ProfileLevel(Main) / AllowFrameReordering(false) / AllowTemporalCompression /
MaxKeyFrameInterval(100) / MaxKeyFrameIntervalDuration(30) / ExpectedFrameRate(30) /
AverageBitRate / DataRateLimits  → 全部 OK（4 条被软件编码器拒绝但不致命）
>>> 出码帧=10 编码错误=0  ✅
```

### 4) 汇编定位
`ResetVTCompressionSession`（VA 0x1fb120）内：
```
0x1fb2db  movl $1,%edi ; movl $0xb,%esi ; movl $3,%edx ; xor %ecx,%ecx
0x1fb2ec  callq 0x944770                 ; 特性/试运行判定
0x1fb2f3  je    0x1fb31a                 ; 没过 → 不设
0x1fb2fc  movq <低延迟键槽位>,%rax        ; _kVTVideoEncoderSpecification_EnableLowLatencyRateControl
0x1fb303  movq (%rax),%rcx
0x1fb30d  movq <___kCFBooleanTrue>,%rdx   ; ★ 值恒为 true
0x1fb314  callq -[NSMutableDictionary setObject:forKeyedSubscript:]
```
另有 UU 自带的降级字符串（说明它自己也认为这条路可能失败）：
`VTCompressionSessionCreate failed (status={}), retrying without EnableLowLatencyRateControl`
`hw accl disabled with EnableLowLatencyRateControl, retrying without it`

## 修复（第 5 类补丁 lowlat）

把「值加载」指令的字面量池指针从 `___kCFBooleanTrue` 改为 `___kCFBooleanFalse`

| 位置 | 改前 | 改后 |
|---|---|---|
| file `0x1ff30d`（VA `0x1fb30d`） | `48 8b 15 1c d1 94 00` → `___kCFBooleanTrue` | `48 8b 15 14 d1 94 00` → `___kCFBooleanFalse` |

定位方式（版本自适应，不硬编码偏移）：结构特征
`48 8b 05 <d> / 48 8b 08 / 48 8b 35 <d> / 48 8b 15 <d>`，
并用 `otool -Iv` 的符号槽位自校验（键槽位必须等于 `_kVTVideoEncoderSpecification_EnableLowLatencyRateControl`，
值槽位必须落在 `___kCFBooleanTrue/False`）——**唯一命中才动手**。

## 验证

- 三态 round-trip：官方原版 → 打 5 类补丁 → 反向还原 → 与官方原版**逐字节一致**（`cmp` 通过）
- 与前一版装机库的代码区差异 = **1 字节**（正是这条位移的低字节 `0x1c→0x14`）
- 字节级复核：补后该指令确实装载 `___kCFBooleanFalse`（VA 0xb48428）
- `patch_tool.py check`：`patched / audio patched / encoder patched / metalgate patched / lowlat patched`

## 五类补丁全景（本机无 Metal + 无硬编的必需组合）

| # | 补丁 | 位置 | 作用 |
|---|---|---|---|
| 1 | 视频 | `0x180241` | 采集改走 CoreGraphics（不走 ScreenCaptureKit） |
| 2 | 音频 | `0x1790d1 / 0x179243 / 0x17936a` | 音频不走 ScreenCaptureKit |
| 3 | 编码器 | `0x1ff28a` | `EnableHardwareAcceleratedVideoEncoder` → false |
| 4 | Metal 门禁 | `0x1ff1d3 / 0x1ff35c` | Metal 设备为空不再 return false（否则 error 12） |
| 5 | **低延迟RC** | `0x1ff30d` | `EnableLowLatencyRateControl` → false（否则 -12902） |

## 残留风险 / 兜底

- 关掉低延迟后，VT 走软件编码：1080p@8FPS 预计 CPU 约 0.5~0.8 核（本机 i5-2520M 双核四线程，可承受；
  若发烫/卡顿，后续可把 `UUSHIM_TARGET_FPS` 降到 5 或在 UU 侧降分辨率/码率）
- 装机必须**重启被控进程**（UURemoteServer），否则跑的还是旧代码
- UU 自动更新会覆盖补丁 → 重跑 install 自动重新定位全部 5 类补丁点

## 命令

```bash
# 安装（App 内是 root:wheel，需要 sudo）
sudo bash uu.sh cg-install
# 体检
python3 patch_tool.py check /Applications/UURemote.app/Contents/Frameworks/libstreamer.dylib
# 装完 + 客户端连过一次后验编码（查日志看 UU 实际走了哪套采集器）
bash uu.sh verify
# 回退
sudo bash uu.sh cg-restore
```
